## Task 3 – Generate and read an SBOM

I continued using `phishing-training-platform` for this task.

The goal of this task is to generate a Software Bill of Materials (SBOM), scan it for known vulnerabilities, and investigate one reported CVE.

### Scan observations

Syft scanned the entire project directory by default, including the local `venv` and development tools such as `act`. As a result, the generated SBOM also included those components.

### Investigated vulnerability

I selected:

```text
GHSA-389r-gv7p-r3rp
CVE-2026-45022
```

**Affected package**

```text
github.com/go-git/go-git/v5
```

**Detected version**

```text
v5.16.5
```

**Fixed version**

```text
v5.19.0
```

#### What is the vulnerability?

The vulnerability affects the `go-git` library.

Certain malformed Git commit and tag objects could be parsed differently from the official Git implementation.

Additionally, the signing and verification logic operated on reconstructed commit data rather than the original raw Git object bytes.

As a result, a commit signature could appear valid even though the underlying object differs from the original bytes stored in the repository.

#### Who is affected?

The affected versions are:

```text
github.com/go-git/go-git/v5 < 5.19.0
github.com/go-git/go-git/v6 <= 6.0.0-alpha.2
```

Projects using these versions to parse, sign, or verify Git objects may be affected.

#### What is the fix?

Upgrade to:

```text
go-git v5.19.0
```

or later.
